## Справочник `City`

### Город

| Вызов | Что возвращает |
| --- | --- |
| `city.status()` | словарь: город, страна, срок сдачи, результат, ступень, сколько попыток использовано по каждой активности, K ярмарки |
| `city.K` | число K ярмарки вашего города (при трёх совпадениях выручка `(K + 1)·s`) |
| `city.me()` | полная карточка города: `"city"`, `"country"` (в т. ч. `"status"`, `"deadline_at"`), `"rules"`, `"stats"` (в т. ч. `"overprofit"` — результат, `"usage"`, `"limits"`), `"rewards"` |
| `city.rename(name, coat)` | меняет название (2–40 символов) и герб; возвращает карточку |

Результат города — вся выручка минус всё вложенное. Результат 0 — то же, что продать весь товар на рынке.

### Ярмарка — `city.fair(kind, lot=1)`

- `kind` — вид товара, целое от 0 до 5;
- `lot` — вложение `s`, целое от 1 до 5 ящиков.

```python
r = city.fair(kind=0, lot=1)
r["outcome"]["wants"]      # [вид товара каждого из трёх покупателей], например [0, 4, 0]
r["outcome"]["matches"]    # число покупателей, которым нужен ваш товар: 0–3
r["revenue"]               # выручка; r["invested"] — вложено, r["profit"] = revenue − invested
```

### Фестиваль — `city.festival(target, lot=1)`

- `target` — номер квартала 0–36 (выручка `36·s`, если сцена там), `"west"` — кварталы 1–18
  или `"east"` — кварталы 19–36 (выручка `2·s`, если сцена в этой половине);
- `lot` — вложение `s`, от 1 до 5.

```python
r = city.festival("west", 1)
r["outcome"]["quarter"]    # квартал, где была сцена
r["revenue"]
```

### Радио

| Вызов | Что делает / возвращает |
| --- | --- |
| `city.catalog()` | таблица песен: индекс `id`, столбцы `title`, `artist`, `genre`, `level` (аудитория `v`, 1–9) |
| `city.play_broadcast(decide, lot=5)` | проигрывает эфир целиком (36 решений) по вашему правилу; таблица из 36 строк: `broadcast`, `pos`, `song`, `level`, `m`, `buy`, `lot`, `revenue` |
| `city.radio_state()` | словарь: `broadcast` (номер эфира), `position` (номер следующей песни, 0 — эфир не начат), `next_m`, `played`, `previous` (предыдущий эфир), `can_play`, `finished` |
| `city.radio_step(buy, lot=1)` | одно решение вручную: купить паузу после следующей песни (`buy=True`) или нет; в ответе `["outcome"]`: `song`, `level`, `m` |
| `city.radio_log(n)` | порядок песен (список id) в эфире `n`; эфир 0 — исходный порядок до начала |
| `city.radio_logs()` | все прошедшие эфиры: `{номер эфира: [id песен]}` |

**Правило `decide`.** Функция `decide(played, previous, catalog, m)` вызывается перед каждой песней и
возвращает `True`, если нужно купить паузу после **следующей** песни:

- `played` — список id песен, уже прозвучавших в этом эфире (в начале эфира пустой);
- `previous` — порядок песен в предыдущем эфире;
- `catalog` — таблица песен, как `city.catalog()`;
- `m` — средняя аудитория ещё не прозвучавших в этом эфире песен.

```python
def decide(played, previous, catalog, m):
    return False                 # ваше правило

b = city.play_broadcast(decide, lot=5)
b[b.buy]                         # купленные паузы
```

`play_broadcast` начинает эфир с начала. Если эфир уже начат через `radio_step`, доиграйте его
тем же `radio_step`.

### История — `city.history(activity)`

Все ваши попытки одной активности таблицей pandas, по строке на попытку, по порядку.

| `activity` | Столбцы |
| --- | --- |
| `"fair"` | `idx`, `kind`, `lot`, `want1`, `want2`, `want3` (желания покупателей), `matches`, `revenue` |
| `"festival"` | `idx`, `target`, `lot`, `quarter` (квартал сцены), `revenue` |
| `"radio"` | `idx`, `broadcast`, `pos` (номер песни в эфире), `buy` (1 — пауза куплена), `lot`, `song`, `level`, `m`, `revenue` |

```python
fest = city.history("festival")
xs = fest["quarter"].tolist()
```

### Палата, прогноз, страна

| Вызов | Что делает |
| --- | --- |
| `city.claim(activity, verdict, text)` | заявка в Экономическую палату: `activity` — `"fair"`, `"festival"` или `"radio"`; `verdict` — `"exploit"` (эксплойт есть) или `"fair"` (активность честная); `text` — что нашли, как собирали данные, какие числа получили |
| `city.claims()` | ваши заявки таблицей: `activity` (`fair`, `festival`, `radio` или `budget` — бюджетный план), `verdict`, `status` (`pending` — на проверке, `approved`, `rejected`), `teacher_comment` |
| `city.forecast(mean, low, high, text)` | бюджетный план (п. 4.2) — тоже заявка в Палату: ожидаемый итог `mean`, диапазон `low ≤ mean ≤ high` и обоснование `text`. За подтверждённый план город получает знак «Надёжный бюджет» |
| `city.country()`, `city.news()` | карта страны и лента новостей |

По каждой активности (и по бюджетному плану) может быть только одна заявка на проверке. Отклонённую заявку можно исправить
и подать снова. Заявки и прогноз можно отправить и на сайте стенда, в разделе «Палата».

## Офлайн-режим — `MockCity`

```python
from econlab import MockCity
offline = MockCity(K=city.K, seed=1)
offline.festival("west", 1)
```

`MockCity` повторяет методы, правила и формат ответов стенда, но все активности в нём **честные**:
желания покупателей, кварталы фестиваля и порядок песен в каждом эфире выбираются независимо
и равновероятно. Эксплойт в офлайн-режиме не найти. Попытки стенда не тратятся, заявки и прогнозы
никуда не отправляются. Нужен, чтобы отлаживать код и ботов.

## Ошибки — `EconError`

Ошибки стенда приходят как исключение `EconError`: `e.message` — текст, `e.code` — код,
`e.status` — HTTP-код ответа.

| `e.code` | Сообщение | Что делать |
| --- | --- | --- |
| `limit` | «Все … попыток использованы» | запас этой активности закончился |
| `not_started` | «Стенд ещё не открыт» | дождитесь открытия, дата — у преподавателя |
| `closed` | «Срок сдачи прошёл» | попытки закрыты |
| `bad_lot`, `bad_kind`, `bad_target` | неверное вложение, вид товара или цель фестиваля | проверьте аргументы |
| `in_progress` | «Текущий эфир уже начат» | доиграйте эфир через `radio_step` |
| — (`status` 401) | «Токен не найден» | проверьте секрет `ECON_TOKEN` или попросите преподавателя выдать новый токен |

```python
try:
    city.festival("west", 1)
except EconError as e:
    print(e.code, e.message)
```

Если запросов слишком много, пакет сам делает паузы и повторяет запрос. Не запускайте несколько
ботов одной команды одновременно.
